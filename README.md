# 게임 네트워크 모니터

**사용할 실행 파일은 이 폴더의 `GameNetworkMonitor.exe` 하나이며, 현재 버전은 0.1.5입니다.** 앞으로 업데이트해도 파일 이름과 로그 위치를 유지합니다. 과거 버전 ZIP과 배포 사본 폴더는 정리했으며, 별도 버전 백업을 만들지 않습니다.

현재 0.1.5는 카드 이름·설명과 표시를 쉽게 정리했으며 전체 컴파일·화면 검사를 통과했습니다. 수집·자동 저장 기능은 0.1.4에서 자체 검사·루프백 자동 기록 통합 검사를 통과했습니다. 실제 게임의 관리자 ETW 수집과 게임 중 성능은 추가 확인이 필요합니다. 자세한 상태는 `VALIDATION.md`를 확인하세요.

선택한 게임의 TCP/UDP 송수신 메타데이터, 이 PC 네트워크 어댑터의 트래픽, PC와 공유기 사이의 ICMP 응답을 한 화면에 기록하는 Windows 프로그램입니다.

## 실행

`GameNetworkMonitor.exe`를 실행합니다. Windows 10/11 64비트와 .NET Framework 4.8 환경용이며, 별도 드라이버·Python·Node·PresentMon 설치가 필요하지 않습니다. 실행파일만으로 사용할 수 있습니다.

1. 게임을 실행한 다음 **목록 갱신**에서 실제 게임 프로세스를 선택합니다. 런처와 게임 프로세스는 다를 수 있습니다. 실행 중인 `TheDivision2`를 우선 표시하지만 다른 프로그램도 선택할 수 있습니다.
2. 인터넷에 연결된 **이 PC의 네트워크 어댑터**를 선택합니다. 공유기 주소는 해당 어댑터의 게이트웨이에서 가져옵니다. VPN·가상 어댑터·AP 구성에서는 실제 공유기 주소와 다를 수 있으므로 확인해 주세요.
3. **측정 시작**을 누르면 게임 송수신·전체 통신 프로그램·외부 ICMP 수집이 함께 시작됩니다. 별도 체크박스는 없습니다. 게임을 선택하지 않아도 프로그램별 통신량·PC·공유기·외부 ICMP를 측정합니다. 외부 비교 대상은 기본 `1.1.1.1`이며, 주소를 비워도 시작할 때 기본값을 사용합니다.
4. 게임을 플레이하면 측정 중인 전체 구간을 자동 저장·분석합니다. **접속지**에서 현재 세션의 원격 IP/포트를, **기록 · 분석**에서 자동 요약과 저장 위치를 확인합니다.
5. **중지** 또는 창 닫기로 수집을 끝냅니다. 전체 기록과 `summary.txt`를 자동 저장합니다. 새 측정을 시작하면 새 폴더를 만들며 이전 폴더는 남습니다. CSV를 직접 내보낼 필요가 없습니다.

## 현재 기록 기능

- **공유기까지의 연결 상태**는 내 PC가 공유기에 확인 요청을 보내 답을 받는 시간과 답이 없던 비율을 보여줍니다. **이 PC의 데이터 사용량**은 선택한 랜선·Wi-Fi 연결에서 모든 프로그램이 초당 주고받는 양입니다. 각 값에 마우스를 올리면 설명을 확인할 수 있습니다. 오류·버린 패킷은 측정 시작 이후 누적입니다.
- **방금 끊김 · 표시** 버튼을 제거했습니다. 게임 송수신 수집과 외부 ICMP 비교 체크박스도 제거하고 측정 시작 시 항상 켜지도록 했습니다. 관리자 창으로 다시 열어도 유지됩니다.

- **전체 통신 프로그램**을 기존 ETW 수집에서 기본 집계합니다. 상위 20개 제한과 체크박스를 제거했으며, 각 측정 구간에 TCP/UDP 통신이 관측된 프로그램의 이름·PID·인스턴스·송수신 속도·누적량을 `process-traffic.csv`에 저장하고 **통신 프로그램** 탭에 표시합니다. 관리자 실행이 필요하며 게임 선택 없이도 사용할 수 있습니다. 통신하지 않은 프로그램은 기록 대상이 아닙니다.
- **게임 접속지**의 프로토콜·로컬/원격 IP와 포트·누적 송수신량·이벤트 수·TCP 재전송을 `game-endpoints.csv`에 변경이 있을 때 저장합니다. 화면의 100행 제한과 별개로 보관 중인 전체 접속지 최대 512개를 기록 대상으로 사용합니다. PC의 초당 송수신 패킷 수도 `samples.csv`에 저장합니다.
- 프로그램별 값은 **모든 어댑터의 TCP/UDP**이고 PC 카드는 선택한 한 어댑터의 전체 통계입니다. 범위·이벤트 집계·전달 시간이 달라 두 값을 직접 차감하거나 인터넷 업로드 속도로 단정하지 않습니다. 미선택 프로그램의 IP·포트·패킷 내용은 해석하거나 기록하지 않습니다.
- 게임 송수신량을 **이벤트가 수집기에 도착한 최근 2초 기준**으로 집계합니다. 늦게 도착한 이벤트가 이미 집계창 밖이라는 이유로 전송량이 0이 되는 문제를 줄였습니다. 실제 회선의 초 단위 전송량과 같지는 않습니다.
- 이벤트 발생 시각과 앱 도착 시각을 분리해 기록합니다. 화면의 **마지막 수신 관측 이후**는 도착 시각 기준이며, **기록 전달 지연**은 ETW 수집 지연입니다. 게임 서버 핑이 아닙니다. 과거 발생 이벤트가 최근 도착한 경우는 수신 공백과 구분합니다.
- PC 송신 10MB/s 이상과 최근 공유기 RTT 20ms 이상이 함께 관측된 구간을 별도 후보로 표시합니다. 세션의 프로그램별 최대 송신 상위 5개도 요약합니다. 같은 시각의 변화이며 특정 프로그램이 지연의 원인이라는 판정은 아닙니다.
- 작은 ICMP 시간 초과 비율도 `0.016%`처럼 표시합니다. 수집을 끈 설정과 수집 실패를 구분하며, PID 재사용·식별 실패·집계 한도 초과도 불확실 상태로 표시합니다.

다음 플레이에서는 기본 설정으로 측정을 시작하세요. 먼저 송신 상위에 어떤 프로그램이 나타나는지 확인하고, 불필요한 통신이라면 해당 프로그램에서 전송을 잠시 멈춘 구간과 평소 구간을 비교할 수 있습니다. 앱이 다른 프로그램을 자동 종료하거나 송신을 제한하지는 않습니다.

게임별 수집에는 Windows ETW 시스템 로거를 사용할 권한이 필요합니다. 권한 부족이면 상단에 **게임 수집 안 됨**과 안내 배너를 표시합니다. 배너의 **관리자 모드 열기**를 누르면 Windows UAC 승인을 요청합니다. 승인 후 새 창은 게임·어댑터·대상 주소 선택을 유지하며, **측정 시작**을 직접 눌러야 수집합니다. 이전 창의 측정은 멈추고 기존 기록은 내보낼 수 있도록 남겨둡니다. UAC를 취소하면 현재 측정은 계속됩니다.

실행파일을 우클릭해 **관리자 권한으로 실행**해도 됩니다. 앱이 사용자 동작 없이 UAC를 열거나 사용자 그룹·보안 정책을 변경하지는 않습니다. 관리자 상태에서도 실패하면 수집 상태의 실패 단계·오류 코드를 확인해야 합니다. 일반 권한에서도 PC 어댑터와 ICMP 검사는 사용할 수 있습니다.

독점 전체 화면 위 오버레이는 제공하지 않습니다. 보조 모니터 또는 게임의 창/테두리 없는 창 모드와 함께 사용할 수 있는 일반 창입니다. 첫 버전에는 FPS 수집이 없습니다.

## 자동 기록과 전체 구간 분석

실행 파일 옆 `logs/날짜-시각-고유ID/` 폴더에 측정 세션마다 다음 파일을 만듭니다. 쓰기 가능한 폴더에서 프로그램을 실행하세요. **측정 시작을 누른 동안만 기록**하며 창을 닫으면 수집도 끝납니다.

| 파일 | 내용 |
| --- | --- |
| `samples.csv` | 약 1초마다 전체 세션의 게임 송수신·어댑터 통계·공유기/외부 ICMP 상태·ETW 수집 상태 |
| `probes.csv` | 개별 ICMP 응답·시간 초과·오류, 정확한 시각·대상·RTT. 전체 세션의 통계 계산에 사용 |
| `process-traffic.csv` | 모든 어댑터에서 통신이 관측된 전체 PID·이름·인스턴스·측정 간격·송수신 속도·누적량. 같은 측정 구간의 중복 저장 제외 |
| `game-endpoints.csv` | 선택 게임의 접속지별 프로토콜·로컬/원격 IP:포트·누적 바이트/이벤트·재전송·마지막 관측 시각. 변경된 누적 표본이며 개별 패킷 기록이 아님 |
| `marks.csv` | 이전 기록 형식과의 호환용 파일. 수동 표시 버튼을 제거했으므로 새 세션은 헤더만 있음 |
| `settings.txt` | 선택한 프로세스·어댑터·검사 대상·수집 설정 |
| `session.txt` | 시작/종료 시각·종료 사유·기록 수·저장 오류 상태 |
| `summary.txt` | 중지하거나 창을 닫을 때 저장하는 전체 세션 통계와 이상 구간 후보 요약 |

**기록 폴더 열기**로 파일을 확인할 수 있습니다. 이후 이 폴더의 기록을 분석하면 수동 표시 없이도 전체 구간에서 변화를 찾을 수 있습니다. 프로그램의 자동 요약은 규칙 기반이며, 요약 화면은 측정 중 약 10초마다 갱신합니다.

- 원시 ICMP 결과에서 전체 응답 RTT 평균·최대·p95, 시간 초과 비율, 연속 시간 초과를 계산합니다. 화면의 겹치는 60초 집계 값을 합산하지 않습니다.
- 공유기 RTT 20ms 이상, 외부 RTT 150ms 이상, 2회 이상 연속 ICMP 시간 초과와 게임 수신 공백을 후보로 표시합니다. 같은 종류는 2.5초 이내면 합칩니다. 앱 도착 기준 공백과 ETW 전달 지연을 분리합니다.
- 게임 수집 권한 부족·표본 공백·어댑터 미측정·ETW 누락을 별도로 표시합니다. 빈 값은 0으로 간주하지 않으며 누적 카운터는 차이와 초기화를 구분합니다.
- 자동 요약은 전체 세션 통계와 최근 후보 최대 100개를 보관합니다. 원본 CSV는 전체 측정 구간을 보존하므로 나중에 모든 후보를 다시 분석할 수 있습니다.
- 메뉴·대기 상태에서도 수신 공백이 생길 수 있습니다. 후보만으로 체감 끊김이나 공유기·ISP·게임 서버 장애를 확정하지 않습니다. FPS·실제 게임 서버 RTT·UDP 종단 간 손실률은 기록하지 않습니다. 자동 요약의 프로그램별 송신 상위 5개는 빠른 확인용이며, 전체 프로그램별 원본은 `process-traffic.csv`에 있습니다.

게임 중 자원 사용을 제한하기 위해 동시에 추적하는 PID는 최대 2,048개이고 120초간 활동이 없는 PID는 정리합니다. 이름 조회 실패·종료·PID 재사용은 불확실 상태로, 집계 한도나 유효하지 않은 PID로 제외된 이벤트는 상태와 CSV에 기록합니다. 게임 접속지는 최대 512개를 보관하며 한도 교체 횟수도 화면과 `samples.csv`에 기록합니다. 이 한도 사이에서 사라진 접속지와 ETW 누락 이벤트까지 완전히 복구할 수는 없습니다. 누적량은 해당 추적 구간에서 관측한 값입니다.

로깅은 우선순위가 낮은 별도 스레드에서 처리하고 약 1초마다 파일 버퍼를 비웁니다. 기록 대기열은 최대 4,096개 배치와 UTF-16 문자 16M개로 제한해 디스크 지연 시 메모리 증가를 막습니다. 디스크 쓰기 실패·대기열 초과는 오류를 표시하고 측정을 멈춥니다. 강제 종료·전원 차단·디스크 장애 때 최근 기록이나 종료 요약은 남지 않을 수 있습니다. 파일을 자동 삭제하지 않으므로 오래 사용한 기록은 필요에 따라 정리하세요.

## 지표를 읽는 방법

| 지표 | 의미 |
| --- | --- |
| 게임 송수신 KiB/s, 이벤트/s | 선택한 PID의 TCP/UDP Windows ETW 이벤트가 보고한 크기와 횟수. 최근 약 2초를 앱 도착 시각 기준 100ms 버킷으로 집계합니다. TCP 재전송 이벤트는 정상 송신 합계와 분리합니다. |
| TCP 재전송 이벤트 | 이 세션에서 관측한 TCP 재전송 횟수. 실제 패킷 손실 비율이 아니며, UDP에는 해당하지 않습니다. |
| 마지막 수신 관측 이후 | 해당 PID의 수신 이벤트가 앱에 도착한 뒤 경과한 시간입니다. 이벤트 발생 시각 기준 경과와 별도로 기록합니다. 전달 대기·메뉴·통신 방식에 영향을 받으므로 이것만으로 장애를 판단하지 않습니다. |
| 기록 전달 지연 | 최근 2초에 앱으로 전달된 선택 PID 이벤트의 발생→도착 차이 평균·최대. 게임 RTT가 아닙니다. |
| 접속지 | 관측한 프로토콜, 로컬/원격 IP·포트와 추적 구간 누적치. 게임 서버·로그인·음성·기타 통신을 자동으로 구분하지 않습니다. 화면은 최근 관측 100행이며, 자동 기록 대상은 보관 중인 전체 접속지 최대 512개입니다. |
| 공유기 응답 시간 | 입력한 공유기 주소에 확인 요청을 보내 답을 받기까지의 시간. 약 1초마다 검사하며 대기 제한은 900ms입니다. Windows가 0ms로 보고한 현재값은 `1 ms 미만`으로 표시합니다. |
| 답이 없던 비율 | 최근 60초의 시간 초과 횟수 ÷ 정상 응답 또는 시간 초과 검사 수. 주소 조회·권한·도달 불가 오류는 따로 표시하고 비율에서 제외합니다. 검사 요청 제한/차단도 영향을 줍니다. |
| 응답 시간 흔들림 | 연속해서 답을 받은 두 검사의 응답 시간 차이의 크기를 평균한 값. 작을수록 응답 시간이 일정합니다. 실패를 사이에 둔 두 응답은 연결하지 않습니다. |
| 이 PC의 데이터 사용량 | 선택한 랜선·Wi-Fi 연결에서 모든 프로그램이 초당 주고받는 데이터양입니다. 게임·브라우저·다운로드·같은 집 안 파일 전송을 포함하며, 인터넷 회선의 최대 속도나 다른 기기의 사용량을 나타내지는 않습니다. |
| PC 어댑터 오류·폐기 | 측정 시작 시점 대비 어댑터가 보고한 수신/송신 오류·폐기 카운터 증가량. 게임별 또는 원격 경로 손실과 다릅니다. 연결 끊김/카운터 초기화 때는 미측정으로 표시합니다. |
| 수집 누락 이벤트·버퍼 | Windows ETW 수집 과정에서 빠진 기록 수. 실제 네트워크 패킷 손실과 다릅니다. 0이라고 실제 게임 통신이 무손실이라는 뜻은 아닙니다. |

ETW 이벤트 수는 회선의 실제 패킷 수와 같지 않을 수 있습니다. 분할·병합·오프로딩 등의 영향을 받습니다. **특정 게임 UDP 통신의 종단 간 손실률은 이 앱에서 계산하지 않습니다.** 게임이 제공하는 통계·로그를 연동할 수 있을 때 별도 기능이 필요합니다.

선택한 프로세스가 종료되면 다시 선택해야 합니다. 동일 이름의 새 프로세스나 자식 프로세스를 자동으로 따라가지 않습니다. 프로세스 시작 시각을 확인해 PID 재사용에 따른 다른 프로그램 수집을 막습니다.

## 공유기별 차이

게임 수집, PC 어댑터 통계, PC↔공유기 ICMP는 공유기 기종과 독립적입니다. 앱을 기종마다 다시 만들 필요가 없습니다.

다른 기기까지 포함한 WAN/LAN 트래픽·포트별 폐기 등 **공유기 내부 통계**는 공유기가 제공하는 별도 연동 방식이 있어야 합니다. 현재 공유기 전체 통계 연동은 포함하지 않습니다. 이 앱은 공유기 관리 화면에 로그인하거나 비공개 API를 추정 호출하지 않으며 공유기 설정도 변경하지 않습니다.

## 기록과 자원 사용

- 실행 직후에는 측정하지 않습니다. 자동 시작·상주 서비스·주기적 외부 감시를 등록하지 않습니다.
- 자동 파일 기록은 측정 중 전체 세션을 보관합니다. 화면 그래프는 최근 120개 표본, 메모리는 최근 7,200개 표본을 유지합니다. 기록·메모의 자동 업로드는 없습니다.
- **최근 CSV 내보내기**는 메모리에 남은 최근 2시간 표본의 별도 사본과 같은 이름의 `.marks.csv`를 만듭니다. 전체 기록은 자동 저장 폴더에 있으므로 이 버튼을 누를 필요는 없습니다.
- 선택한 게임 PID는 IP·포트·전송 크기 메타데이터를 집계하고 저장합니다. 다른 PID의 이름·시작 시각으로 구분한 인스턴스·송수신 바이트도 기본 저장합니다. 다른 프로그램의 주소·패킷 본문, 계정 비밀번호, 채팅 내용, 게임 메모리는 읽지 않습니다. 복호화·게임 DLL 주입·입력 자동화·패킷 변경·별도 캡처 드라이버 설치가 없습니다.
- 네트워크 검사 외에 로컬 GPU나 AI 모델을 사용하지 않습니다. 실제 게임 중 오버헤드와 게임별 호환성은 추가 확인이 필요합니다.

## 빌드와 검사

소스는 C# 5 / .NET Framework WPF이며 외부 패키지 의존성이 없습니다. Windows 내장 Framework64 C# 컴파일러를 사용합니다.

```powershell
.\build.ps1
```

기본 빌드는 임시 파일로 컴파일만 확인하고 그 파일을 제거합니다. 프로그램을 실행하지 않으며 현재 배포 실행 파일을 덮어쓰지 않습니다. 배포 파일을 갱신할 때만 다음 명령으로 같은 이름을 교체합니다. 실행 파일이 사용 중이거나 컴파일에 실패하면 기존 파일을 유지합니다.

```powershell
.\build.ps1 -UpdateExecutable
```

아래 명령은 **현재 배포된 실행 파일**을 검사합니다. 화면을 변경한 0.1.5는 `--smoke-test`를 통과했습니다. 수집·저장 기능의 0.1.4는 `--self-test`, `--smoke-test`, `--recording-test`를 통과했습니다. 별도 임시 실행 파일을 실행하지 않았고, 실제 ETW를 시작하는 `--probe-test`는 실행하지 않았습니다.

```powershell
.\GameNetworkMonitor.exe --self-test
.\GameNetworkMonitor.exe --smoke-test
.\GameNetworkMonitor.exe --probe-test
.\GameNetworkMonitor.exe --recording-test
```

`--self-test`는 ETW·ICMP·통계·CSV·선택 값 전달과 자동 저장·주기적 flush·이전 세션 보존·쓰기 실패·규칙 분석을 확인합니다. `--smoke-test`는 측정 없이 초기 화면·권한 안내·자동 기록 탭을 PNG로 렌더링하고 선택 복원이 자동 측정을 시작하지 않는지 검사합니다. 권한 화면은 UI 검사 상태이며 실제 수치가 아닙니다. `--probe-test`는 루프백 ICMP·어댑터·현재 권한의 ETW 시작/종료를 확인합니다. `--recording-test`는 게임/ETW 수집을 끈 WPF 창에서 루프백 ICMP만 사용해 시작·중지·재시작·창 닫기 이후 원본과 요약이 보존되는지 확인합니다. 검사에서 UAC나 실제 게임을 실행하지 않으며 결과는 `tests/`에 저장합니다.
