# PC 인터넷 모니터

내 PC의 연결과 인터넷 검사 결과를 기록하고, **어느 검사에서 언제 실패했고 언제 회복했는지** 확인하는 Windows 앱입니다.

현재 버전은 **0.2.7**이며 저장소 이름은 **`pc-internet-monitor`**입니다. 소스 저장소: [JooWon0712/pc-internet-monitor](https://github.com/JooWon0712/pc-internet-monitor).

## 다운로드

**[PcInternetMonitor.exe 다운로드](https://github.com/JooWon0712/pc-internet-monitor/releases/latest/download/PcInternetMonitor.exe)** · [릴리스 안내](https://github.com/JooWon0712/pc-internet-monitor/releases/latest)

실행 환경은 **Windows 10/11 64비트(x64)**와 **.NET Framework 4.8**입니다. 별도 드라이버·Python·Node 설치는 필요하지 않습니다.

설치 없이 `PcInternetMonitor.exe` 하나를 실행하면 됩니다. 아이콘은 실행 파일에 내장돼 있으며, 기본 기능은 일반 권한으로 사용하도록 구성돼 있습니다. 파일은 기록을 저장할 수 있는 폴더에 두세요. 측정 기록은 실행 파일 옆의 `logs/`, 진단 기록은 `diagnostics/`에 생성됩니다.

릴리스의 `SHA256SUMS.txt`와 `provenance.json`은 파일과 빌드 출처를 확인하려는 사용자를 위한 선택 자료입니다. 앱 실행에는 필요하지 않습니다.

## 다운로드 파일의 출처 확인

v0.2.7부터 배포 EXE는 공개 저장소의 [GitHub Actions 빌드](https://github.com/JooWon0712/pc-internet-monitor/actions/workflows/build.yml)에서 만듭니다. Windows runner에서 빌드·회귀 검사를 수행하고, 생성한 EXE의 SHA-256과 GitHub artifact attestation을 발급합니다. 릴리스에는 이 CI 산출물을 그대로 사용하며, 개인 PC에서 다시 빌드한 파일로 바꾸지 않습니다. 기존 v0.2.6 이하 릴리스는 이 방식의 출처 증명 대상이 아닙니다.

출처 증명은 **파일의 해시와 빌드를 수행한 저장소·소스 커밋·워크플로의 관계**를 검증하는 자료입니다. 백도어가 없다는 증명, 보안 감사, 모든 환경에서의 정상 동작 보장 또는 Windows 게시자 서명(Authenticode)을 뜻하지 않습니다. [GitHub의 출처 증명 설명](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)

현재 EXE에는 Authenticode 서명이 없습니다. GitHub 출처 증명을 제공해도 Windows의 게시자 서명으로 바뀌지 않으므로 SmartScreen 경고나 정책에 따른 차단이 발생할 수 있습니다. [Microsoft의 SmartScreen 설명](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

[GitHub CLI](https://cli.github.com/)를 사용하는 검증자는 다운로드한 EXE가 있는 폴더에서 다음 명령으로 저장소와 서명 워크플로, GitHub-hosted runner의 출처 증명을 확인할 수 있습니다.

```powershell
gh attestation verify .\PcInternetMonitor.exe `
  --repo JooWon0712/pc-internet-monitor `
  --signer-workflow JooWon0712/pc-internet-monitor/.github/workflows/build.yml `
  --source-ref refs/heads/main `
  --deny-self-hosted-runners
```

특정 릴리스의 소스 커밋까지 고정하려면 위 명령에 `--source-digest`와 해당 릴리스 노트의 전체 커밋 SHA를 추가하세요. 함께 받은 증명 파일을 사용하려면 `--bundle .\provenance.json`도 추가할 수 있습니다. 검증에 성공한 저장소·워크플로·커밋과 다운로드한 릴리스가 일치하는지 확인하세요. SHA-256만 비교하면 파일이 같은지는 확인할 수 있지만, 그것만으로 빌드 출처나 안전성이 증명되지는 않습니다.

## 사용

1. 다운로드한 `PcInternetMonitor.exe`를 실행하고 **PC 연결 · 랜선 / Wi-Fi**에서 확인할 연결을 고릅니다.
2. **검사 시작**을 누릅니다. 실행 직후에는 측정을 시작하지 않습니다.
3. 네 가지 검사 결과와 **끊김 · 검사 실패 이력**을 확인합니다.
4. **검사 중지**로 기록을 마무리하고 **기록 폴더**에서 원본과 요약을 확인합니다.

기본 창은 1040×740, 최소 크기는 960×660입니다. PC 연결 선택과 검사 제어는 고정하고 이력 목록 안에서만 스크롤합니다. 차콜 배경의 CLI 스타일을 사용하며 청록은 응답 확인·핵심 값, 노랑은 확인할 관측값, 빨강은 기록 오류로 중지, 회색은 설명·미측정입니다.

Windows 11(빌드 22000 이상)에서는 제목 표시줄과 테두리에도 어두운 색을 적용합니다. Windows 기본 창틀을 유지해 창 이동·크기 조절·최소화·최대화를 사용할 수 있습니다. X는 기록을 마무리하고 앱을 종료합니다. 고대비 모드나 색상 지정을 지원하지 않는 환경에서는 운영체제 기본 모양을 사용하며, Windows 10의 창틀 색상 적용은 보장하지 않습니다.

## 창과 종료

**X, Alt+F4 또는 창 오른쪽 위의 앱 종료 버튼을 누르면 진행 중인 검사와 기록을 마무리하고 프로그램을 완전히 종료합니다.** 창을 숨겨 백그라운드 실행을 유지하거나 시스템 트레이 아이콘을 등록하지 않습니다.

- **최소화하면 진행 중인 검사와 기록을 마무리하고 중지합니다.** 앱 창은 작업 표시줄에 남습니다.
- 창을 복원해도 검사를 자동으로 재시작하지 않습니다. 다시 측정하려면 **검사 시작**을 누르세요.
- 다른 앱으로 전환하거나 다른 창이 앞에 오는 것만으로 검사가 중지되지는 않습니다. 앱 창을 계속 선택한 상태로 둘 필요는 없습니다.
- 종료 후 EXE를 실행하면 새 창을 엽니다. 실행 직후에는 측정을 시작하지 않습니다.

Windows 로그오프·종료 때도 기록을 마무리하고 앱을 종료합니다. Windows 자동 시작이나 별도 서비스는 등록하지 않으므로 PC를 다시 켜면 앱을 직접 실행해야 합니다.

실행 파일을 교체하기 전에 기존 앱을 종료하세요. v0.2.5가 실행 중이면 기존 EXE를 다시 실행해 창을 연 다음 **앱 종료**를 누릅니다. v0.2.4 이하 버전은 기존 트레이 메뉴의 **종료**로 끝냅니다. 새 EXE는 구버전의 숨겨진 창을 복원하지 않으며, 파일을 교체해도 이미 실행 중인 프로세스의 동작은 바뀌지 않습니다.

## 관리자 권한

**현재 기본 기능은 관리자 권한 없이 실행할 수 있습니다.** 일반 실행으로 PC 어댑터 통계, ICMP·DNS·HTTPS 검사와 로컬 기록을 사용합니다. 게임·프로그램별 ETW나 TCP RTT 수집을 시작하지 않으며 관리자 승격이나 UAC 요청을 하지 않습니다.

방화벽·조직 정책·VPN·프록시·검사 대상의 응답 정책에 따라 결과가 달라질 수 있습니다. 실행 파일은 기록을 쓸 수 있는 폴더에 두세요. 일부 검사 실패나 파일 쓰기 오류는 해당 오류로 표시합니다.

## 검사 범위

| 검사 | 확인하는 내용 | 해석할 때 주의할 점 |
| --- | --- | --- |
| 공유기 응답 | 내 PC와 선택 연결의 기본 게이트웨이 사이 ICMP 왕복 | 대상은 보통 공유기이지만 VPN·가상 연결에서는 다를 수 있습니다. |
| 외부 응답 | 내 PC와 기본 외부 대상 `1.1.1.1` 사이 ICMP 왕복 | 공유기·ISP·외부 경로를 통과한 결과입니다. ISP 구간만 분리한 검사가 아닙니다. |
| DNS 이름 조회 | Windows 시스템 이름 조회로 `www.microsoft.com`의 IP 주소 확인 | 시스템 캐시·hosts 결과가 포함될 수 있어 매번 외부 DNS 서버에 새 질의를 보낸다는 뜻은 아닙니다. |
| 웹 접속 · HTTPS | `https://www.gstatic.com/generate_204`의 예상 HTTP 204 응답 확인 | DNS·TCP·TLS·서버 응답을 포함합니다. 순수 회선 핑이 아니며 리디렉션이나 다른 응답 코드는 성공으로 처리하지 않습니다. |

ICMP는 약 1초 간격, 응답 대기 제한 900ms입니다. 최근 응답이 3초 이상 갱신되지 않으면 현재 값을 숨깁니다. Windows가 0ms로 보고하면 `1 ms 미만`으로 표시합니다. 카드의 무응답률은 **최근 60초 시간 초과 ÷ (응답 + 시간 초과)**입니다. 네트워크 도달 불가·라우팅·TTL·MTU 등의 알려진 실패 결과는 **응답/경로 실패**로 따로 집계하고 실패 이력에 반영합니다. 응답/경로 실패와 권한·주소 조회 등의 검사 자체 오류는 무응답률 분모에서 제외해 별도로 표시합니다. 이 비율은 모든 데이터 패킷의 유실률이 아닙니다. 검사를 중지하면 현재 수치와 최근 60초 상세 표시를 비웁니다.

DNS와 HTTPS는 각각 약 5초 간격, 검사 제한 3초로 동작합니다. 최근 완료 결과가 15초 이상 갱신되지 않으면 오래된 값으로 구분합니다. Windows DNS 작업은 즉시 취소되지 않을 수 있으므로 이전 작업이 끝날 때까지 다음 조회를 겹치지 않습니다. 이때 실제 검사 간격은 길어질 수 있습니다.

HTTPS는 Windows/.NET의 기본 인증서 검증과 프록시 설정을 사용합니다. 인증서 검증을 끄거나 TLS 보안 설정을 변경하지 않습니다. 검사 요청에 쿠키나 계정 자격 증명을 넣지 않고, 예상 응답 확인을 위한 작은 요청만 보냅니다. 대용량 다운로드 속도 검사는 하지 않습니다.

선택한 PC 연결의 게이트웨이를 검사 중 약 2초 간격으로 다시 확인합니다. 주소가 바뀌면 공유기 검사만 새 대상으로 시작하고 기존 대상의 열린 이력은 회복 미확인으로 마무리합니다. 조회에 실패하거나 주소를 확인하지 못하면 기존 대상을 유지합니다.

상단의 받기/보내기는 선택한 PC 어댑터의 현재 사용량입니다. 로컬 네트워크 통신도 포함할 수 있으며 인터넷 회선의 최대 속도와 다릅니다. 공유기 전체나 다른 기기의 사용량은 수집하지 않습니다.

## 끊김·검사 실패 이력

- 같은 검사에서 **2회 연속 실패**하면 첫 실패 관측 시각부터 이력을 만듭니다. 명확한 PC 연결 끊김은 한 번의 관측으로 기록합니다.
- DNS 조회·HTTPS 접속·ICMP 응답 실패와 검사 자체 오류를 구분합니다. 어댑터 통계를 읽지 못했다는 이유만으로 연결이 끊겼다고 기록하지 않습니다.
- 성공 결과를 관측하면 회복 시각과 관측 지속 시간을 표시합니다. 시각은 검사로 확인한 시각이며 실제 회선 단절·회복 시각과 차이가 날 수 있습니다.
- 검사 중지, 최소화, X·Alt+F4·앱 종료, 검사 결과의 긴 공백은 **관측 종료 · 회복 미확인**입니다. 이를 회복으로 바꾸지 않습니다.
- 다시 실행하면 이전 세션의 이력을 비동기로 불러옵니다. 이전 실행에서 열린 채 남은 이력도 회복 미확인으로 표시합니다.

시스템 시각이 역행하거나 단조 경과 시간보다 250ms 이상 뒤처지는 경우, 또는 검사 시작·완료 시각이 역전되면 **시스템 시각 변경으로 검사 중지**를 표시하고 마지막 정상 관측을 기준으로 현재 세션을 마무리합니다. 열린 이상 이력은 회복 미확인으로 남으며, **검사 시작**을 눌러 새 기록을 시작할 수 있습니다. 자동으로 재시작하지 않고 진행 시간은 단조 경과 시간을 사용합니다.

## 로컬 기록

검사 세션마다 실행 파일 옆 `logs/날짜-시각-고유ID/` 폴더를 만듭니다. 쓰기 가능한 폴더에서 실행하세요. 새 로그 형식은 6이며 이전 세션 파일은 수정하지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `internet-checks.csv` | 공유기·외부 ICMP와 DNS·HTTPS의 개별 완료 결과, 대상·시각·소요 시간·응답 코드·오류 |
| `connectivity-incidents.csv` | 이력 시작·변경·회복·관측 종료 기록. 같은 ID의 최신 버전이 현재 상태이며 회복과 중지 시각을 구분함 |
| `samples.csv` | 약 1초마다 PC 어댑터 사용량·오류/폐기 누계·ICMP 상태 등의 표본 |
| `probes.csv` | 개별 ICMP 응답·시간 초과·응답/경로 실패·검사 오류 원본. 마지막 `network_failure` 열로 경로 실패 구분 |
| `settings.txt` | 버전·PC 연결·검사 대상·수집 설정·진단 파일 경로 |
| `session.txt` | 기록 수·파일 저장 상태·종료 사유 |
| `summary.txt` | 검사 중지나 앱의 완전 종료 때 생성하는 검사별 통계와 이력 요약 |
| `errors.txt` | 오류가 발생한 세션의 오류 단계·예외 스택 |

이전 기능과의 호환을 위해 `marks.csv`, `process-traffic.csv`, `game-endpoints.csv`, `tcp-rtt.csv`도 생성합니다. **현재 일반 검사에서는 게임·프로그램별 ETW와 TCP RTT를 수집하지 않으므로 해당 기록은 헤더만 남습니다.** 기존 ETW/TCP 코드는 호환성과 회귀 검사를 위해 유지합니다.

앱 수명 주기 진단은 `diagnostics/`에 따로 기록합니다. 마지막 관측 시각은 디스크 쓰기 완료 시각이 아니고, `session.txt`의 `state=completed`는 파일 기록 완료를 뜻하며 정상 앱 종료의 증명은 아닙니다. 디스크 오류·대기열 초과가 생기면 오류로 검사를 멈춥니다. 강제 종료·전원 차단에서는 최근 기록과 종료 요약이 남지 않을 수 있습니다.

측정 기록과 진단 파일은 로컬 데이터이며 Git에서 제외합니다. 배포에는 실행 파일과 공개 빌드 검증 자료만 포함하고 `logs/`, `diagnostics/`, 테스트 산출물과 `outputs/`는 포함하지 않습니다.

## 개인정보와 외부 통신

- **로컬 저장:** 측정 결과는 `logs/`, 앱 진단은 `diagnostics/`에 저장합니다. 앱이 이 파일을 자동 업로드하거나 별도 분석 서버로 보내는 기능은 없습니다.
- **기록에 포함되는 정보:** 검사 시각·대상 주소·응답 시간·HTTP 상태·오류, 어댑터 이름·ID와 트래픽 통계, 실패·회복 이력을 기록합니다. 진단에는 앱 자신의 PID, 실행·종료 정보, 파일 경로와 예외 내용이 포함됩니다. 저장 위치나 오류 내용에 Windows 사용자 이름 같은 환경 정보가 나타날 수 있으므로 공유 전에 주소·ID·경로를 확인하세요.
- **외부 검사 요청:** 연결 확인을 위해 공유기와 `1.1.1.1`에 ICMP, `www.microsoft.com`에 대한 시스템 DNS 조회, `https://www.gstatic.com/generate_204`에 HTTPS 요청을 보냅니다. 검사 대상·DNS 제공자·프록시에는 공인 IP나 조회 도메인 등 일반적인 접속 정보가 전달될 수 있습니다. DNS는 시스템 캐시를 사용할 수 있으며 경로는 Windows 라우팅·VPN·프록시 설정을 따릅니다.
- **현재 기본 기능의 수집 범위:** 다른 프로그램의 패킷 본문·암호·쿠키를 수집하지 않습니다. 앱이 HTTPS 검사 요청에 로그인 정보나 쿠키를 추가하지 않으며 응답 본문을 저장하지 않습니다.
- **배포와 Git:** 공개 EXE에는 개발자의 개인 측정 기록·테스트 결과·분석 자료가 포함되지 않습니다. 로컬 기록과 생성 산출물은 `.gitignore`로 제외합니다. 릴리스에는 EXE와 공개 CI의 해시·출처 증명 자료만 첨부합니다.

## 빌드와 검증

```powershell
.\build.ps1
```

기본 빌드는 컴파일만 확인한 뒤 이번 빌드의 임시 실행 파일을 제거하고, 이번 빌드가 만든 `.build/`가 비어 있으면 폴더도 제거합니다. 기존 폴더와 다른 파일은 보존합니다. 고정 실행 파일을 갱신할 때만 다음 명령을 사용합니다.

```powershell
.\build.ps1 -UpdateExecutable
```

버전별 EXE·테스트 실행 사본·ZIP 백업은 만들지 않습니다. 업데이트는 같은 `PcInternetMonitor.exe`를 교체하며 이미 열린 사용자 창은 강제로 닫지 않습니다. 새 버전은 기존 앱을 완전히 종료한 뒤 다시 실행할 때 적용됩니다.

배포용 EXE는 공개 CI에서 빌드·검사·출처 증명 생성 후 [GitHub Releases](https://github.com/JooWon0712/pc-internet-monitor/releases)에 첨부합니다. 실행 파일과 로컬 기록·테스트 산출물은 `.gitignore`로 Git 추적 대상에서 제외합니다. 로컬 빌드는 개발 확인용이며 CI 릴리스 파일을 대체하지 않습니다.

검사 모드는 고정 EXE를 사용하며 실행마다 고유한 `tests/.run-<GUID>/` 폴더에 테스트 기록·화면·진단 자료를 모읍니다. 검사가 정상 또는 실패로 종료되면 해당 실행이 만든 임시 폴더만 자동 정리합니다. 자식 프로세스를 쓰는 검사는 부모 실행의 임시 폴더를 함께 사용하고 부모가 종료할 때 정리합니다. 실제 `logs/`·`diagnostics/`, 기존 파일과 재사용 가능한 C# 테스트 소스는 정리 대상이 아닙니다.

강제 종료나 전원 차단으로 정리 코드가 실행되지 않거나 파일이 사용 중이면 임시 파일이 남을 수 있습니다. Windows가 실행 중인 EXE를 교체하면서 남기는 `*.exe~RF*.TMP`는 사용 중인 실행 이미지이므로 강제로 자동 삭제하지 않습니다.

| 모드 | 범위 |
| --- | --- |
| `--self-test` | DNS/HTTPS 상태·시간 초과·세대, 이력·로그·아카이브 등 합성 검사와 기존 기능의 회귀 검사 |
| `--smoke-test` | 네 검사·실패/중지 상태·고정 제어·작은 창·이력의 합성 WPF 렌더링 |
| `--recording-test` | 루프백 ICMP와 합성 DNS 결과로 시작·저장·이력 복원·오류·중지·종료 흐름 확인 |
| `--internet-loopback-test` | 로컬 이름 조회와 테스트 전용 HTTP 204/302/시간 초과·중지 확인. 실제 HTTPS/TLS 검증이 아님 |
| `--internet-test` | 실제 시스템 DNS와 공개 HTTPS 검사 대상에 접속하는 명시적 검사 |
| `--internet-recording-test` | 실제 DNS/HTTPS 결과를 별도 테스트 폴더의 CSV·요약까지 기록하는 통합 검사 |
| `--lifecycle-test` | 측정하지 않는 별도 WPF 검사 창의 종료 흐름 |
| `--window-close-test` | X·Alt+F4에 따른 프로세스 종료와 기록 마무리, 최소화 시 검사 중지·복원 후 수동 재시작, 모의 Windows 종료를 확인하는 별도 창 검사 |

경로 실패·게이트웨이 변경·시각 역행 회귀 검사는 실제 OS 시각이나 NIC 설정을 바꾸지 않고 합성 입력으로 검증합니다. 재사용 가능한 C# 테스트 소스만 저장소에 포함합니다. 합성 검사·루프백 검사를 실제 인터넷 장애 재현이나 장시간 성능·일반 권한 실행 검증으로 확대해서 설명하지 않습니다.
